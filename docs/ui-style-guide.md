# UI 风格规范

## 1. 结论

客户端 UI 可以直接做成 `D:\SOFT\Pencli\repos\client.pen` 这一套视觉风格。

推荐实现方式：

- 原生运行时核心继续走 `Supervisor + 本地接口 + WebSocket`
- UI 使用 Web 技术实现
- 桌面壳建议使用 `Tauri`
- 样式建议使用 `Tailwind CSS + daisyUI + 自定义主题变量`

这里的 `daisyUI` 只作为基础组件和主题系统来源，最终视觉不应该停留在默认 daisyUI 观感，而是要贴近 `client.pen` 的终端调度台风格。

## 2. 视觉基调

`client.pen` 的主风格不是传统后台管理，而是：

- 终端调度台
- 大画布工作区
- 少量高对比状态色
- 强边框、弱装饰
- 卡片作为操作对象，而不是信息堆砌

视觉关键词：

- 明亮
- 冷静
- 控制台
- 调度台
- 有边界感
- 状态导向

默认建议以 Light 主题为主，Black 主题作为后续补充或切换主题。

## 3. 从 `client.pen` 提取出的关键视觉规则

### 3.1 主色与表面

从设计稿可直接抽出这套基础色：

- 主背景：`#0A0F1A`
- 顶栏背景：`#111827`
- 画布渐变起点：`#0B1220`
- 面板描边：`#1F2A3A`
- 次级描边：`#263244`
- 主文字：`#F8FAFC`
- 次文字：`#94A3B8`
- 高亮蓝：`#2563EB`
- 成功绿：`#22C55E`
- 警告橙：`#F59E0B`
- 危险红：`#EF4444`

这说明 UI 要走“深底 + 冷色文本 + 少量状态强调色”的方向，不适合做成亮色大卡片后台。

### 3.2 容器层级

整体层级很清晰：

1. 最外层应用壳
2. 顶栏
3. 主画布容器
4. 无限画布层
5. 浮层详情窗 / 独立终端窗口

对应到客户端 UI 时，建议固定成：

- `AppShell`
- `TopBar`
- `WorkspacePanel`
- `CanvasSurface`
- `InspectorDrawer / FloatingWindow`

### 3.3 组件气质

设计稿里的组件并不花哨，但有很强的一致性：

- 圆角中等，常见为 `10px / 16px / 18px`
- 描边存在感强于阴影
- 按钮偏扁平，不做厚重拟物
- 标签使用胶囊形状
- 强调“状态”而不是“装饰”

这意味着实现时应避免：

- 默认 daisyUI 那种过度圆润糖果风
- 泛滥的渐变按钮
- 满屏阴影卡片
- 多种强调色同时竞争

## 4. 页面布局建议

### 4.1 第一版客户端 UI 结构

建议按 `client.pen` 的“调度台”结构来做：

- 顶栏
  - 产品名
  - 服务端连接状态
  - 当前运行模式
  - 添加员工 / 恢复动作
- 左侧或中部主工作区
  - 员工运行时画布
  - 运行状态节点
- 终端详情弹窗
  - 当前员工信息
  - Agent 来源
  - 当前任务摘要
  - CLI 状态与诊断
- 浮层终端窗口
  - 当用户打开某个员工 CLI 时显示独立终端视图

### 4.2 为什么这套样式适合当前客户端

因为当前客户端本质上是：

- 运行时监控器
- CLI 调度台
- 本地恢复入口

它不是 CRM，也不是表格型后台。

所以 `client.pen` 这种“调度画布 + 状态卡片 + 浮层终端”的结构，和实际业务是对齐的。

## 5. 与 daisyUI 的关系

可以参考 daisyUI，但不要停留在 daisyUI 默认视觉。

推荐做法：

- 保留 daisyUI 的主题机制和基础按钮、抽屉、modal、tabs
- 自己覆写颜色 token、圆角、边框、背景、阴影
- 对核心模块使用自定义样式，而不是纯拼默认组件

更直接地说：

- `daisyUI` 负责效率
- `client.pen` 负责审美和结构

## 6. 实现层建议

### 6.1 技术组合

推荐：

- `Tauri`
- `React`
- `Tailwind CSS`
- `daisyUI`
- `React Flow`

原因：

- `Tauri` 负责桌面端壳和原生能力桥接
- `React` 方便搭调度台和多面板 UI
- `Tailwind + daisyUI` 适合快速落主题系统
- `React Flow` 适合无限画布、员工节点、任务关系图

### 6.2 主题策略

第一版建议先做：

- `client-light`
- `client-dark`

其中 `client-light` 作为默认主题。

主题变量至少包含：

- `--color-bg-app`
- `--color-bg-surface`
- `--color-bg-panel`
- `--color-border-strong`
- `--color-border-soft`
- `--color-text-primary`
- `--color-text-secondary`
- `--color-accent-blue`
- `--color-success`
- `--color-warning`
- `--color-danger`

### 6.3 字体建议

`client.pen` 使用的是 `Inter`。

如果后面想更有个性，可以在标题或品牌位加入第二字体，但第一版建议先收敛，保持：

- 全局 `Inter`
- 强依赖字重和颜色层级
- 不依赖夸张字体造型

## 7. 第一版视觉实现范围

第一阶段建议只先实现以下视觉模块：

1. Light 应用壳
2. 顶栏状态区
3. 员工运行时卡片
4. 无限画布容器
5. 终端详情弹窗
6. 独立终端浮层

先把整体气质和信息密度做对，再慢慢补：

- 浅色主题
- 更复杂的节点交互
- 动效细节
- 主题切换

## 8. 第一版不建议做的事情

- 直接照搬 daisyUI 默认主题
- 做成表格 + 卡片堆叠式后台
- 在所有区域都加重阴影
- 同时用很多强调色
- 做成营销官网式 hero 布局

## 9. 落地建议

当前项目文档层面已经可以明确：

- 运行时架构按 `Supervisor + UI` 分层
- UI 风格以 `client.pen` 为视觉基准
- 组件实现参考 daisyUI，但必须做自定义主题和表面系统

下一步进入实际开发时，建议先从以下顺序落地：

1. 建立主题 token
2. 先搭应用壳和顶栏
3. 再实现员工运行时卡片和终端详情弹窗
4. 最后接入无限画布和终端浮层
